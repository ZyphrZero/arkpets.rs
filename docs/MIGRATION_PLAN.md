# 功能与配置项迁移计划

本计划对应交互动画、过渡、物理和渲染设置清单，分批实现并验证。已交付能力与平台验证记录见 [迁移记录](MIGRATION.md)，当前使用方式见 [README](../README.md)。原版字段和默认值以 Java 仓库 `assets/ArkPetsConfigDefault.json` 为依据；字段对照不表示已支持直接导入原始 Java 配置。

## 已完成：整体不透明度

| 原字段 | 默认值 | 语义 |
| --- | --- | --- |
| `opacity_normal` | `1.0` | 常规不透明度，同时用于预览和普通桌宠 |
| `opacity_dim` | `0.75` | 透明模式／鼠标穿透时的不透明度，实际值不超过常规不透明度 |

预览和桌宠先按 Spine slot 顺序完成 GPU 离屏合成，再对完整角色统一应用一次不透明度，避免肢体重叠处重复淡化。wgpu 与 Glow 都有实现，正常绘制不进行 GPU 像素读回；透明模式不等于悬停自动变暗。

已有 macOS Metal 回归使用佩佩、荒芜拉普兰德、Friston-3 三个真实模型，验证 25% 不透明度下 RGBA 是正常合成结果的四分之一，容许 `2/255` 量化误差，同时检查鼠标穿透、窗口身份、暂停和位置保持。该结果不代表与 Java 后处理逐像素一致，也不替代 Windows、Linux 或受控背景下的系统合成验证。

## 阶段 1：交互、过渡与物理

### 配置与行为

| 功能 | 原字段 | 原默认值 | 迁移语义 |
| --- | --- | --- | --- |
| 允许触发交互动画 | `behavior_allow_interact` | `true` | 控制交互动作触发；与是否允许拖拽分离，不能关闭交互动画后连带禁用桌宠移动 |
| 动画交叉过渡 | `render_animation_mixture` | `0.3` 秒 | 禁用／快速／标准／慢速对应 0／0.1／0.3／0.6 秒，控制 Spine 动作之间的混合，与常规属性过渡独立 |
| 常规属性过渡 | `transition_duration` | `0.3` 秒 | 相同四档时长，覆盖位置、朝向翻转、不透明度和描边强度；0 秒立即完成 |
| 缓动函数 | `transition_type` | `EASE_OUT_CUBIC` | `LINEAR`、`EASE_OUT_SINE`、`EASE_OUT_CUBIC`、`EASE_OUT_QUINT` |
| 重力加速度 | `physic_gravity_acc` | `800.0` | 控制自由运动的垂直加速度 |
| 空气阻力加速度 | `physic_air_friction_acc` | `100.0` | 控制运动中的减速，不是按速度相乘的阻尼比例 |
| 地面摩擦加速度 | `physic_static_friction_acc` | `500.0` | 控制接触支撑面时的水平减速 |
| 最大水平运动速度 | `physic_speed_limit_x` | `1000.0` | 限制水平速度，覆盖拖拽释放的惯性 |
| 最大垂直运动速度 | `physic_speed_limit_y` | `1000.0` | 限制垂直速度，覆盖拖拽释放的惯性 |

常规属性过渡覆盖位置、翻转、不透明度和阶段 2 接入的描边强度。Java 还对动作垂直偏移使用相同过渡；该项依赖多形态动作与偏移语义，仍未迁移。

界面使用原版四档下拉选项，保留并显示配置／命令提供的自定义时长。核心共享 `TransitionPreset` 映射；进程内 `ConfigureTransitions(TransitionUpdate)` 允许独立更新两个时长和缓动函数，未指定字段保持执行时的当前值。时长采用秒数而非 UI 索引，支持精确自定义值；全量与局部更新共用校验，非法参数整条拒绝。外部 Agent 尚不能连接此接口，后续适配器可复用它。

物理设置按 Rust 的逻辑坐标与系统 DPI 换算工作。保留已存在的配置语义：**最大速度为 0 在 Rust 中表示停止该轴惯性／自由运动，Java 中表示不限制该轴速度**。主动行走由“行走速度”独立控制。不得直接将 Java 的零值当作等价 Rust 配置导入，也不得无提示改变已有 Rust 偏好的行为。

Rust 保存使用 `animationMixDuration`、`propertyTransitionDuration`、`easing`，兼容读取旧 `transitionDuration`、`opacityTransitionDuration`、`opacityTransition`，分别保持骨骼混合、常规属性过渡时长和缓动函数的原有值。`allowInteract` 现在只控制交互动画，新 `allowDrag` 默认开启并独立控制拖拽。旧物理对象带有 `drag` 且没有 `airFriction`／`groundFriction` 时，两项新摩擦默认为 0，保留原重力、指数阻尼和停止阈值；调整新阻力后清除旧阻尼项，恢复默认则使用原 Java 的 800／100／500 加速度默认值。新增测试通过实际 `eframe::Storage` 的 RON 序列化和反序列化验证迁移与重新保存。

本轮 macOS 原生回归 `cargo run --locked --example verify-macos-behavior` 已检查暂停骨骼下的连续翻转、真实窗口位置中间点／终点、零时长移动，以及完成后 2.5 秒内只有 3 次桌宠回调。多屏内角与 DPI 过渡由几何和状态测试覆盖，实际混合 DPI 热插拔、Windows 和 Linux 桌面行为仍需实机复测。Windows 设置回归脚本坐标已按实际 egui 布局测量更新，不把这项布局检查视为 Windows 实机通过。

### 验收重点

- 关闭交互动画后不再由交互触发动作，拖拽可独立启停；预览和桌宠行为一致，边界转向与手动动作不被误禁用。
- 动画混合与属性过渡分别调整；覆盖四种曲线、0 秒、过渡中改目标／改参数、翻转经过零缩放时的坐标稳定性。
- 两项时长均为禁用／快速／标准／慢速四档，使用统一映射；覆盖自定义值原样显示与保存、命令局部更新、非法参数整条拒绝及 UI 同步。配置应用成功与视觉过渡完成分别处理。
- 物理状态与视觉过渡职责分明；检查拖拽释放、暂停／恢复、多屏边界及不同 DPI，避免平滑显示引入错误的释放速度或越界位置。
- 五项参数保存、重启恢复并应用于相关运行时；验证最大速度为 0、极小窗口、非有限参数和异常输入，错误不能伪装为成功。
- 暂停时必要的属性过渡仍可完成，完成后停止额外高频重绘；关闭、隐藏或最小化预览不引入重复动画推进。

## 阶段 2：描边、阴影与高质量后处理

| 功能 | 原字段 | 默认值 | 原版选项／语义 |
| --- | --- | --- | --- |
| 描边条件 | `render_outline` | `1`，拖拽时 | 关闭 `0`、拖拽 `1`、按下 `2`、前台焦点 `3`、始终 `5`；`4` 是保留值 |
| 手动模式描边条件 | `render_outline_emphasis` | `3`，前台焦点 | 与普通条件共用选项，进入手动模式后替代普通条件 |
| 描边颜色 | `render_outline_color` | `#FFFF00FF`，黄 | 原 UI 提供黄、橙、白、青；配置存 RGBA |
| 手动模式描边颜色 | `render_outline_emphasis_color` | `#FFBB00FF`，橙 | 手动模式下替代普通颜色 |
| 描边宽度 | `render_outline_width` | `2.0` | 原 UI 为 `1`、`1.5`、`2`、`3`、`5`，用于合成纹理的像素邻域采样 |
| 阴影强度 | `render_shadow_color` | `#000000BB` | 原 UI 为禁用 `00`、轻微 `77`、标准 `BB`、重墨 `FF` 的黑色 Alpha |
| 高质量滤波 | `render_shader_high_quality` | `true` | 切换描边／阴影算法，与图集双线性过滤无关 |

原 UI 的“操控中”实际判断 `tray.keepAnim != null`，即手动／保持动作模式，不是正在拖拽或暂停。前台条件依赖原生窗口焦点，不是鼠标悬停；按下和拖拽分别对应输入状态。描边强度使用常规过渡，颜色在原版中立即切换。

效果作用于已经合成的整张角色：高质量 shader 使用 5×5 网格中除中心的 24 个高斯加权邻域点，低质量版本使用 16 个圆周采样点。两者仅对低 Alpha 边缘区域添加描边或阴影；阴影是轮廓周围的阴影，不是地面投影或可调光源。高质量采样跨度可达两倍描边宽度，低质量圆周半径为描边宽度，不能假定开关只改变平滑度。

wgpu 与 Glow 已维持相同的配置和预乘 Alpha 约定：角色覆盖描边，描边覆盖阴影，再对完整结果统一乘不透明度；没有原样套用 Java 的直通颜色混合。宽度采用随系统 DPI 换算的逻辑像素，条件、颜色、宽度、阴影与质量实时生效；描边强度共用常规属性过渡。相较 Java 需要重新创建角色，Rust 无需重建角色即可调整这些效果。

验收覆盖普通／手动模式的五种条件、焦点切换、按下到拖拽、透明模式、描边淡入淡出、阴影禁用与各强度、不同缩放及 DPI。使用三个真实模型检查效果越界裁剪、透明边缘和双窗口共享资源，并分别验证 wgpu 与 Glow；不得仅以人工矩形替代真实资源回归。

当前条件与过渡逻辑有单元回归；`verify-macos-effects` 在三个真实模型上检查两种质量的外侧描边／黑色阴影、手动颜色、组合效果的 25% 逐像素透明度及背景透明。OpenGL 另在 macOS 上通过精确重叠图形的 7 阶段像素回归；Windows 上的原生焦点、按下／拖拽与两后端仍需实机复测。

## 阶段 3：MipMap 采样

`render_enable_mipmap` 默认 `true`。Java 加载图集时将每页 `minFilter` 设为 `MipMapLinearLinear` 并启用 MipMap，不修改放大过滤 `magFilter`。关闭时保留 atlas 自带的过滤配置，并非强制关闭资源已声明的 MipMap；它也不是 MSAA。

Rust 开启时保留完整基础层并生成完整层级，使用三线性缩小采样；关闭时强制基础层线性采样，这是与 Java 保留 atlas 配置的明确差异。wgpu 从预乘颜色生成层级，Glow 调用原生 Mipmap 生成；只在模型或开关变更时更新 GPU 纹理，两个窗口共享。测试覆盖基础层不变、奇数尺寸层级、透明色边缘及三个真实模型的缩小采样开关差异，不据此宣称性能收益。

## 阶段 4：窗口边界预计算

| 功能 | 原字段 | 默认值 | 原 UI 值 |
| --- | --- | --- | --- |
| 边界大小 | `canvas_coverage` | `0.8` | 最宽 `0.45`、较宽 `0.65`、标准 `0.8`、较窄 `0.9`、最窄 `0.95` |
| 边界计算方式 | `canvas_sampling_interval` | `4` | 极精确 `1`、精确 `4`、粗略 `16`、极粗略 `64` |

`coverage` 是所有动作采样叠加图的 Alpha 裁剪阈值，值越大通常得到越紧的边界，不是几何留白比例。`sampling_interval` 是以固定 30 FPS 基准计算的抽帧间隔，不是运行时每隔 N 帧刷新边界。

Java 在角色初始化时按形态遍历动画，用带 Alpha 的样本叠加生成 FBO，读回后从四边每隔 2 像素扫描达到阈值的内容，并保留随缩放变化的边距；结果按形态缓存。短动画取中间帧，高阈值无法找到合适边界时降低阈值重试。它不是每帧求当前骨骼包围盒。

Rust 已采用 CPU 资源采样：独立临时 Spine 在指定时刻输出真实裁剪后网格，按 UV 双线性读取原图 Alpha，在最长边 256 的分析 mask 上累计后裁剪；渲染仍使用原始图集与系统 DPI。与 Java 的 RGBA8 FBO 和每 2 像素扫描不同，这里是浮点累积、逐分析像素扫描，并按全部动画采样，尚未按多形态分组。权重分母使用实际姿态数，静态零时长动画也可采样，因此不声称逐像素等价。加色 slot 不增加当前 Rust 合成 Alpha，不纳入覆盖 mask。

累计 Alpha 预计算最多 4096 姿态，超出或完全透明时明确报错。`Attack`、`Attack_*`、`Skill_*` 另按 240 Hz（含端点，最多 16384 姿态）求非零 slot Alpha 的已索引网格范围，加一个分析像素余量，扩大独立的绘制画布，防止短暂伸出的武器被裁断。这部分不栅格化，不改变原 Alpha 范围或累计权重；物理区域的左右、顶部使用裁剪结果，底部沿用 Java 的骨骼 `y=0` 地面基准；任务栏高度和拖拽按物理区域计算，原生窗口按画布偏移定位，脚下动画与效果留白不抬高角色。不是 Java 原版的等价行为。阈值过高导致空结果时会降低阈值，并把实际值显示给用户。缓存最多 32 组资源版本和配置结果，模型文件改变后需重新载入。边界与骨骼缩放基准分离；重新计算只改变边界范围，不放大骨骼，也不改变正在播放的动画、图集或暂停状态。重新计算按钮和模型载入会应用选择，恢复默认也重新计算默认边界。

三个真实模型的 CPU 测试已覆盖阈值收紧、抽帧间隔、全透明图集拒绝、共享三角形边、非法参数和采样预算。Apple M2 的单线程 release 实测：极精确间隔 1 分别为约 146／205／66 ms（613／964／292 姿态）；极粗略间隔 64 为约 3.5／4.9／2.3 ms。该结果是边界分析耗时，不是帧率或其他机器的性能保证。

验收使用真实动画覆盖宽幅动作、短动画、半透明附件、空形态、极小／异常尺寸；检查翻转、缩放、DPI、描边／阴影扩展及动作切换后的裁剪。边界改变还须回归拖拽命中、落地高度、多屏部署和位置保持，避免只验证截图尺寸。模型、缩放或相关参数改变后，旧缓存不得继续误用。

## 原版实现定位

以下路径相对于 Java Ark-Pets 仓库，仅用于语义核对，不是 Rust 构建依赖：

- `desktop/src/cn/harryh/arkpets/controllers/BehaviorModule.java`：交互、两项过渡的四档选项、缓动函数和物理设置。
- `desktop/src/cn/harryh/arkpets/controllers/SettingsModule.java`：渲染控件、选项与保存逻辑，`initConfigRendering`。
- `core/src/cn/harryh/arkpets/ArkPets.java`：`render` 中的普通／手动模式描边条件，`setTransparentMode`。
- `core/src/cn/harryh/arkpets/ArkChar.java`：属性过渡初始化、两阶段合成、`adjustCanvas` 采样与形态缓存。
- `core/src/cn/harryh/arkpets/render/DynamicOrthographicCamara.java`：`getFittedInsert` 的 Alpha 扫描裁剪。
- `assets/shaders/ComplexFragment.glsl`、`ComplexFragmentLow.glsl`：描边和阴影两套后处理算法。
- `core/src/cn/harryh/arkpets/assets/SkeletonLoader.java`：`loadSkeletonDataWith` 的图集 MipMap 设置。

各阶段按影响范围先运行相近模块测试，再执行 feature 测试、格式、Clippy 和构建。桌面效果、原生透明和实际多屏行为需要平台实机验证，编译通过不能替代；交付记录实际执行的场景与尚未覆盖的平台。
